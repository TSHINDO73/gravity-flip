# スマホ対応（タッチ操作）設計

日付: 2026-10-27

## 目的

URLを送った友人が、スマホ（主にAndroidのChrome）でそのまま遊べるようにする。PCでの遊び方と見た目は変えない。

## 決めたこと

- 横持ち専用。縦持ちのときは「横向きにしてください」と表示する
- ボタンは標準型（左下に ←・→、右下に 反転・ジャンプ、右上に ↻ やり直し）
- ボタンは Phaser の画面内に描き、Phaser のタッチ入力で受け取る（HTMLのボタンや外部プラグインは使わない）
- 実機確認は Android の Chrome で行う。iPhone 固有の対応はしないが、標準的な作りにして最低限動くようにする

## 部品の構成

```
キーボード ─┐
            ├─→ Controls ─→ Player / GameScene
タッチボタン ─┘
```

### 新規

| ファイル | 役割 |
|---|---|
| `src/logic/inputRules.js` | 画面に依存しない計算。指の位置とボタンの当たり判定、押されたボタンの集計、前フレームとの比較による「押した瞬間」「離した瞬間」の判定 |
| `src/objects/Controls.js` | キーボードとタッチの状態を合わせ、フレームごとに `left` `right` `jumpDown` `jumpPressed` `jumpReleased` `flipPressed` `restartPressed` を渡す |
| `src/objects/TouchPad.js` | 5つのボタンを描き、複数の指（pointer）を追跡して、押されているボタンの集合を返す。タッチ端末のときだけ作る |

### 変更

| ファイル | 内容 |
|---|---|
| `src/objects/Player.js` | キーを直接読まず、`update` で受け取った Controls の状態を使う。ジャンプ・コヨーテ・先行入力・反転の挙動は変えない |
| `src/scenes/GameScene.js` | Controls（とタッチ端末では TouchPad）を作る。やり直しは `restartPressed` を使う（ゴール後の待ち時間中は無視する既存の挙動を保つ） |
| `src/scenes/TitleScene.js` | 画面タップでも開始する。タップ時に全画面表示と横向き固定を試みる。タッチ端末では案内文を「タップでスタート」にする |
| `src/scenes/ClearScene.js` | 画面タップでもタイトルへ戻る。既存の0.3秒の受付待ちはタップにも適用する。タッチ端末では案内文を「タップでタイトルへ」にする |
| `src/main.js` | Phaser の拡大縮小設定（比率を保って画面に合わせる、中央寄せ）と、同時タッチ数の追加 |
| `index.html` | viewport の設定、ピンチ拡大・文字選択・長押しメニューの抑止、縦持ち時の案内（CSSのみ） |

## 画面と操作の詳細

### 画面サイズ

- ゲーム画面（960×540）は比率を保って画面いっぱいに拡大・縮小する。余白は黒（今の背景色 `#111`）
- `index.html` に `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no">` を追加する
- `body` とゲーム画面に `touch-action: none`、`user-select: none`、`-webkit-touch-callout: none` を指定する

### タッチ端末の判定

- `window.matchMedia('(pointer: coarse)').matches` が真なら、タッチ端末として扱う
- PCではボタンを描かず、案内文も変えない

### 縦持ち時の案内

- `@media (orientation: portrait) and (pointer: coarse)` のときだけ、画面全体を覆う案内（「📱 スマホを横向きにしてください」）を表示する
- CSSだけで作り、ゲームの処理には触れない

### ボタン

- 座標はゲーム画面上の値（960×540基準）。円形、半径45px
- 配置（中心座標）

| ボタン | 中心 x | 中心 y |
|---|---|---|
| ← | 80 | 460 |
| → | 200 | 460 |
| 反転 | 760 | 460 |
| ジャンプ | 880 | 460 |
| ↻ やり直し | 910 | 50（半径30） |

- 白の半透明（通常は不透明度0.25、押している間は0.5）。ラベルの文字も描く
- カメラのスクロールに影響されないように固定表示し、HUDより手前に描く
- ステージは画面の高さいっぱいを使うため、下のボタンは床に重なる。半透明なので床やトゲは透けて見える

### 複数の指と指の移動

- フレームごとに、触れている全ての指の位置を調べ、その位置にあるボタンの集合を「押されているボタン」とする
- そのため、指を ← から → へ滑らせると、← が離されて → が押された扱いになる
- 2本の指が同じボタンに乗っていて片方を離しても、もう片方が乗っていれば押されたまま扱いにする
- 「押した瞬間」「離した瞬間」は、前のフレームの集合と今のフレームの集合を比べて求める
- Phaser の同時タッチ数は、既定（1つ）に3つ追加して4つにする

### 押しっぱなし事故の防止

- ブラウザのフォーカスが外れたとき（`blur`、ページが非表示になったとき）と、タッチがキャンセルされたとき（`pointercancel`）は、すべてのボタンを離した扱いにする

### キーボードとの合成

- 各入力は「キーボード または タッチ」で合成する
  - `left` / `right` / `jumpDown`：どちらかが押されていれば真
  - `jumpPressed` / `flipPressed` / `restartPressed`：どちらかがこのフレームで押された瞬間なら真
  - `jumpReleased`：ジャンプの入力（キーボードとタッチのどちらか）が、このフレームで「押されている」から「押されていない」に変わったとき真

### タイトル画面・クリア画面

- 画面のどこをタップしても進む（`pointerdown`）
- クリア画面は既存の0.3秒の受付待ちと、二重遷移防止を、タップにも適用する
- タイトル画面のタップ時に、全画面表示（`this.scale.startFullscreen()`）と横向き固定（`screen.orientation.lock('landscape')`）を試みる。失敗や非対応は無視してそのまま始める
- タッチ端末では案内文を「タップでスタート」「タップでタイトルへ」にする。PCでは今の文言のまま

## テスト

### 自動テスト（`tests/inputRules.test.js`）

- 当たり判定：ボタンの中、外、境界のちょうど上
- 押されているボタンの集計：指なし、1本、2本が別々のボタン、2本が同じボタン、どのボタンにも乗っていない指
- 押した瞬間・離した瞬間：前後のフレームの比較
- 指を滑らせたとき：← から → への移動で、← が離され → が押された扱いになる

### ブラウザでの確認（Playwright のスマホ表示モード）

- 横画面（タッチあり）：ボタンの位置、画面の拡大縮小、HUD と ↻ が重ならないこと
- 縦画面（タッチあり）：案内が表示されること
- PC表示：ボタンが出ず、今と見た目が変わらないこと

### 実機確認（Android の Chrome）

- PCで `python -m http.server 8123 --bind 0.0.0.0` を動かし、同じWi-Fiのスマホから `http://<PCのIPアドレス>:8123/` を開く（初回に Windows のファイアウォールの許可を求められることがある）
- 確認項目
  1. → を押しながらジャンプできる
  2. ← から → へ指を滑らせて方向転換できる
  3. 押しっぱなしにならない
  4. タップでスタートし、全画面になる
  5. 縦にすると案内が出る
  6. 3ステージを通しでクリアできる
- 押しやすさや手の疲れの感想を聞き、ボタンの大きさと位置を調整する

### 既存機能の確認

- PCのキーボード操作（移動、可変ジャンプ、反転、R、タイトルとクリア画面のキー）が今までどおり動く
- BEST 記録の保存と表示が今までどおり動く
- 既存の自動テストがすべて通る

## 対象外

- 縦持ちでの操作
- iPhone 固有の対応（Safari での全画面表示など）
- ゲームパッド対応
- ボタン配置のカスタマイズ
