# リメイク版（見た目と UI の刷新）設計

日付: 2026-10-28

## 目的

遊び方（移動・ジャンプ・重力反転・コイン・敵・トゲ・中間旗・ゴール・ベスト記録・スマホ操作・演出）はそのままに、見た目を高彩度・高品質なドット絵に作り直し、UI をすっきりさせる。友人に見せる作品の質を上げるのが目的で、販売はしない。

公開中の版（https://tshindo73.github.io/gravity-flip/）を置き換える。気に入らなければ元に戻せるようにする。

## 決めたこと

- 素材は Pixel Adventure 1（Pixel Frog、CC0）だけを使う。有料の Pixel Adventure 2 は使わない
- 主人公は Pink Man。敵は Virtual Guy を赤茶に色替えしたもの
- 背景はプログラムで描く空・雲・丘（視差スクロール）。ステージごとに 1 面は昼、2 面は夕焼け、3 面は夜（星空）
- HUD はプレイ画面の外、上部の帯に、白枠のパネルを3つ並べる
- スマホのボタンはプレイ画面の外、左右の列に置く
- キャラは素材の2倍で表示し、当たり判定もキャラに合わせて広げる。通れなくなる高さ1マスの空間は高さ2マスに広げる
- 効果音は今のまま（Kenney）
- 日本語の文字は DotGothic16（OFL）を、使う文字だけにサブセット化して使う

## 戻せるようにする

- 作業を始める前に、main の現在のコミットにタグ `v1-classic` を付けて GitHub に push する
- 戻すときは、main をこのタグの状態に戻す変更をコミットして push する（履歴は消さない）

## 縮尺

| 項目 | 今 | リメイク後 |
|---|---|---|
| 1マス（`TILE`） | 36px（18px × 2） | 32px（16px × 2） |
| 表示倍率（`SCALE`） | 2 | 2 |
| プレイ画面 | 960 × 540 | 960 × 480（15マス） |
| HUD の帯 | なし（画面内に重ねる） | 高さ 60px、プレイ画面の上 |

- 長さに関わる物理定数は 32/36（= 8/9）倍にする。時間に関わる定数（`COYOTE_MS`、`BUFFER_MS`）と比率（`JUMP_CUT`）は変えない。これで「何マス跳べるか」「何秒で着地するか」は今と同じになる

| 定数 | 今 | リメイク後（8/9 倍） |
|---|---|---|
| `GRAVITY` | 1400 | 1400 × 8/9 |
| `RUN_SPEED` | 220 | 220 × 8/9 |
| `JUMP_VELOCITY` | 560 | 560 × 8/9 |
| `MAX_FALL_SPEED` | 900 | 900 × 8/9 = 800 |
| `ENEMY_SPEED` | 60 | 60 × 8/9 |

- 演出の値のうち長さに関わるもの（砂ぼこりを出す勢い 350px/秒、粒の速さ、輪の半径）も 8/9 倍にする

## 画面の構成

| | PC | タッチ端末（`(pointer: coarse)`） |
|---|---|---|
| ゲーム全体の大きさ | 960 × 540 | 1280 × 540 |
| 左右の列 | なし | 左 160px・右 160px |
| HUD の帯 | (0, 0) 〜 960 × 60 | (160, 0) 〜 960 × 60 |
| プレイ画面 | (0, 60) 〜 960 × 480 | (160, 60) 〜 960 × 480 |

- ゲーム本体（GameScene）のカメラは、プレイ画面の範囲だけを映す（カメラのビューポートを設定する）
- HUD とスマホのボタンは、GameScene と同時に動く別のシーン（`UIScene`）に描く。構造上、UI とキャラは重ならない
- 拡大縮小は今と同じ（比率を保って画面いっぱい、中央寄せ）
- ステージの高さが 15 マスに満たないときは、今と同じくプレイ画面の中で上下中央に置く

## 絵の差し替え

素材は必要なファイルだけを `assets/pa/` にコピーし、わかりやすい名前を付ける。使わなくなった Kenney の画像（`assets/tiles.png`、`assets/characters.png`）は削除する。

| 要素 | 素材 | 表示 |
|---|---|---|
| 地形ブロック | `Terrain/Terrain (16x16).png` の草と土の 3×3（シートの列 6〜8・行 0〜2、1 行 22 枚） | オートタイル（下記） |
| 主人公 | `Main Characters/Pink Man/` の Idle・Run・Jump・Fall・Hit | 20 コマ/秒。天井に立つときは上下反転 |
| 敵 | `Main Characters/Virtual Guy/Run` を色替え（色相 +0.5、彩度 ×1.2、明度 ×0.8） | 色替えはスクリプト `tools/make-enemy.py` で一度だけ行い、出力画像を保存する |
| コイン | `Items/Fruits/Apple.png`（回転アニメ）、取得時は `Items/Fruits/Collected.png` | 呼び名はコードでは「コイン」のまま |
| トゲ | `Traps/Spikes/Idle.png` | 天井のトゲは上下反転 |
| 中間旗 | `Items/Checkpoints/Checkpoint/` の No Flag（未通過）→ Flag Out（通過した瞬間）→ Flag Idle（通過後） | 絵の下端をマスの下端に合わせる。当たり判定は今と同じ1マス |
| ゴール | `Items/Checkpoints/End/End (Idle).png` | 絵の下端をマスの下端に合わせる。当たり判定は今と同じ1マス |
| 砂ぼこり | `Other/Dust Particle.png` | 今の白い丸の代わり |
| ゴールの粒 | `Other/Confetti (16x16).png` | 今の色付きの丸の代わり |

### オートタイル

- 各ブロックの上下左右が空いているか（ステージの外は「ブロックあり」とみなす）から、3×3 のどのタイルを使うかを決める
- 行：上が空いていれば草の行（行 0）。上がふさがり下が空いていれば、草の行を上下反転して使う（天井側にも草を付ける。天井も歩く場所なので）。上下ともふさがっていれば土の行（行 1）
- 列：左が空いていれば左端（列 6）、右が空いていれば右端（列 8）、どちらでもなければ中央（列 7）。左右とも空いていれば中央
- この判定は画面に依存しない関数にして、自動テストする

### 当たり判定

| | 素材上の大きさ（px） | 画面上の大きさ（px） | マス換算 |
|---|---|---|---|
| 主人公 | 幅 10 × 高さ 26 | 20 × 52 | 約 0.6 × 1.6 |
| 敵 | 幅 14 × 高さ 22 | 28 × 44 | 約 0.9 × 1.4 |

- 体は今と同じく足元側に寄せる（重力が上向きのときは画像の上側）
- 敵の踏みつけ判定、トゲ・コイン・旗・ゴールの判定の考え方は変えない

### 高さ1マスの空間をなくす

- 「上下ともブロックにはさまれた、ブロックでないマス」をステージから無くす。該当するのは今はステージ 2 だけ（10 行目のトンネル、列 12〜18 と 23〜30）
- 直し方はステージごとに判断する。ステージ 2 のトンネルは、天井を1マス上げて高さ2マスにする（9 行目の該当部分を空ける）
- 自動テストで、全ステージに該当するマスが無いことを確かめる

### 背景

- 背景は `Background` モジュールにまとめ、ステージごとの色の組（空の上・下の色、丘の2色、雲の色、星の有無）を受け取って描く
- 空は 8px 刻みの段階グラデーション。雲と丘は低い解像度で描いてから 4 倍に拡大し、ドットらしく見せる
- 雲は 0.2 倍、丘は 0.4 倍の速さでカメラに追従させる（視差スクロール）。空は動かさない
- 色の組：1 面は昼（青空・緑の丘・白い雲）、2 面は夕焼け（橙〜桃の空・紫がかった丘・桃色の雲）、3 面は夜（紺の空・暗い緑の丘・灰色の雲・小さな星）
- タイトル画面とクリア画面は 1 面の背景を使う

## UI

### 文字

- 英数字は素材の `Menu/Text/Text (White) (8x10).png` をビットマップフォントとして読み込み、3 倍で表示する。収録文字は A〜Z、0〜9、`. , : ? ! ( ) + -`
- 日本語は DotGothic16 を使う。ゲーム内で使う文字だけにサブセット化した woff2 を同梱し、ライセンス文書（OFL）も一緒に置く。読み込みが終わってからタイトル画面を描く

### HUD（上部の帯）

- 紺（#181830）の帯に、白枠（太さ 3px）・紺塗りのパネルを3つ：左にリンゴのアイコン＋「X12」、中央に「STAGE 1-1」、右に時計のアイコン＋「1:23.4」
- タッチ端末では ↻（やり直し）ボタンを右の列の上部（帯と同じ高さ）に置く
- コイン取得時に HUD を動かす演出は入れない（前回の試遊で不要と判断済み）

### タイトル画面

- 1 面の背景。ロゴ「GRAVITY」「FLIP」を 8 倍のドット文字＋影で表示
- BEST をパネルで表示（記録がなければ出さない）
- 「タップ / Z でスタート」を点滅表示（タッチ端末では「タップでスタート」、PC では「Z・スペース・Enter でスタート」）
- 操作説明「←→ 移動　Z ジャンプ　X 反転　R やり直し」の1行は PC だけに表示
- 主人公が右下で待機アニメ
- 開始の操作（キー・タップ・全画面・横向き固定）は今のまま

### クリア画面

- 1 面の背景に、中央のパネル：「CLEAR!」、リンゴ×数、時計＋タイム
- 更新した項目にはピンク（#ff5078）の「NEW!」バッジ、更新しなかった項目には小さく「BEST 1:20.1」のように前回の記録
- 案内「タップ / Z でタイトルへ」（タッチ端末と PC で今と同じく出し分ける）
- 戻る操作（0.3 秒待ち、二重遷移防止）は今のまま

### スマホのボタン

| ボタン | 中心 x | 中心 y | 半径 |
|---|---|---|---|
| ← | 42 | 430 | 36 |
| → | 118 | 430 | 36 |
| 反転 | 1200 | 330 | 40 |
| ジャンプ | 1200 | 440 | 46 |
| ↻ | 1200 | 30 | 26 |

- 紺の半透明（不透明度 0.8）に白い縁と白いアイコン。押している間は明るくする
- 座標はゲーム全体（1280 × 540）基準。押し方の仕組み（複数の指、指を滑らせる、最初のフレームは押した瞬間を出さない、アプリ切り替え時の解除）は今のまま

## テスト

### 自動テスト

- オートタイル：周りの状態ごとに正しいタイル番号と上下反転が選ばれる（上だけ空き、下だけ空き、左右の端、四方ふさがり、ステージの外）
- ステージの検証：全ステージに「上下ともブロックにはさまれた、ブロックでないマス」が無い
- 縮尺：8/9 倍した定数で、ジャンプで届く高さ（`JUMP_VELOCITY² / (2 × GRAVITY)` をマス数にしたもの）が今と同じ
- スマホのボタン：新しい座標で、当たり判定のテストを書き直す
- 既存のテストがすべて通る

### 画面の確認（Playwright）

- PC とスマホ表示で、タイトル・ステージ 1〜3・クリア画面を撮影し、見本どおりか
- HUD とボタンがプレイ画面に重ならない
- `?debug=1` で、当たり判定がキャラの絵に合っている
- コンソールにエラーが無い

### ユーザーによる確認（PC と Android）

1. 見た目の印象（高彩度・高品質になったか、すっきりしたか）
2. 操作感が今と変わっていないか
3. 広げたトンネルなど、ステージの遊びやすさ
4. スマホのボタンの押しやすさ
5. 3 ステージを通しでクリアできるか

## 対象外

- 効果音・BGM の変更
- ステージの追加や大きな作り直し（高さ1マスの空間を広げる以外）
- 主人公の出現・退場アニメ（素材の Appearing / Desappearing）
- Pixel Adventure 2 の購入（敵の見た目が不満なら、敵だけ Kenney の絵に戻す）
